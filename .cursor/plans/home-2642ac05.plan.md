# Home Alpha Landing Plan

## 1. Reference & Data Audit

- Inspect `screencapture-alphaplatform-net-Home-Alpha-2025-11-18-14_18_50.png` to catalog required sections, typography, color palette, slider layout, and spacing rules that must be mirrored.
- Map each visual section to the closest existing `PageSection` slug or define new slugs to store editable copy in `database/Data/utils/IntroSections.php` and ensure the required course/category/blog datasets already come from `PageService::getPageSections()`.

## 2. Ads Backend API

- Create `app/Models/Ad.php`, migration `database/migrations/..._create_ads_table.php`, factory, and `database/seeders/AdSeeder.php` with fields like `title`, `tagline`, `image`, `cta_label`, `cta_url`, `is_active`, `display_order`, `starts_at`, `ends_at`.
- Add `app/Http/Resources/AdResource.php` plus `app/Http/Controllers/Api/AdController.php` that returns only active ads ordered by `display_order`.
- Register `Route::get('api/ads', [AdController::class, 'index'])->name('api.ads.index');` in `routes/web.php` (or a dedicated `routes/api.php` if preferred) and document the contract.

## 3. Intro Page Data & Settings

- Extend `database/Data/PageData::getHomePages()` with a `home-alpha` entry referencing a new `IntroSections::getHomeAlphaSections()` definition that captures hero copy, stats, featured sliders, testimonials, CTA text, etc.
- Update `PageSeeder` (and, if necessary, add a one-off data migration) so the `home_page` setting points to the new `home-alpha` page ID by default.
- Amend `App\Services\PageService::getPageSections()` to treat `home-alpha` like the richer templates (e.g., load `newCourses`, `topInstructors`, `categoryTopCourses`, `blogs`, etc.) so the React page has the datasets it needs.

## 4. Frontend Plumbing

- Add an `Ad` TypeScript interface (e.g., `resources/js/types/ad.d.ts`) and expose it via the existing type barrel if needed.
- Implement a reusable `useAds` hook under `resources/js/hooks/use-ads.ts` that fetches `/api/ads`, handles loading/error states, and caches results client-side (leveraging `axios`).
- Build slider primitives in `resources/js/components/ads/` (e.g., `ad-card.tsx`, `ad-slider.tsx`) using the existing `Carousel` wrappers (`resources/js/components/ui/carousel.tsx`) plus Embla autoplay for the hero banners, matching the reference gradients/overlays.
- Add any bespoke utility classes or gradients required for the Alpha look to `resources/css/app.css` (keeping them scoped to the landing selectors).

## 5. Home Alpha React Page

- Create `resources/js/pages/intro/home-alpha.tsx` with partials under `resources/js/pages/intro/partials/home-alpha/` (hero + ad slider, stats strip, grade/category grids, testimonials, blog teasers, CTA panel, etc.).
- Treat each grade as a category: reuse the existing category logic but surface grade-specific labels, display placeholder artwork where a grade lacks imagery, and show friendly empty-state messaging whenever a datasets array is empty (courses, categories, tutors, ads, etc.).
- Use `getPageSection(page, '<slug>')` for editable copy while consuming shared datasets from `IntroPageProps` and the ads hook. Inject placeholder imagery wherever an instructor/tutor lacks a profile photo.
- Reuse existing cards (e.g., `CourseCard2`, `CategoryCard3`) but wrap them in Alpha-specific styling (overlapping cards, blurred gradients, fixed-width columns) so the layout matches the screenshot.
- Ensure responsiveness, RTL readiness, and `LandingLayout` compatibility so customization buttons keep working.

## 6. Verification & Documentation

- Run `php artisan migrate` + `php artisan db:seed --class=AdSeeder` to provision the ads table/content; confirm `/api/ads` returns the seeded payload.
- Rebuild assets with `npm run dev`/`npm run build` to verify the new landing layout renders at `/` after updating the `home_page` setting.
- Document how to manage Ads (CRUD expectations) and how to switch back to old home variants (e.g., update `settings` table) in `README.md` or an ops note.
